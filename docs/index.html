Scaffold DDD instalável para Laravel

CqFeature gera a estrutura DDD da Cq (Module → Domain → Feature) — Shared, Features CRUD/customizadas, Migrations, Factories, Routes e Tests — a partir de um único comando Artisan. É a evolução do FeatureMaker, agora reutilizável e 100% configurável via config/cqfeature.php.

DDD Module / Domain / Feature Artisan Stubs publicáveis Zero hardcode

O que é o CqFeature?

O CqFeature é um gerador de scaffold que materializa a arquitetura DDD da Cq em código. Você informa o módulo, o domínio e as features desejadas, e o pacote cria toda a árvore de arquivos (Entidades, Models, DAOs, Repositories, Controllers, Services, Requests, DTOs, Migrations, Factories, Rotas e Tests) seguindo os padrões do projeto.

Diferente da antiga lib interna FeatureMaker (acoplada ao cq/api e cheia de caminhos/namespaces fixos no código), o CqFeature é um pacote Composer no padrão Cq*: instalável por VCS, com auto-discovery do Service Provider e toda configuração (caminhos, namespaces, rotas, nome do comando e stubs) externalizada para config/cqfeature.php.

Zero hardcode

Caminhos, namespaces, rotas e stubs vêm da config injetada — nenhum literal no código do pacote.

Out-of-the-box

Os defaults reproduzem o comportamento do cq/api: instale e use sem ajustar nada.

Stubs seus

Publique os stubs e edite os templates por projeto — o stub publicado tem precedência.

Portável

Funciona em projetos com estruturas/namespaces distintos apenas ajustando a config.

Regra de ouro (RN-01)
Com a config default, a saída do CqFeature é idêntica à do FeatureMaker original do cq/api. Um teste de equivalência por snapshot é o guardião dessa regra.

O que faz e o que não faz

✓ O CqFeature faz

  • Gerar a camada Shared do domínio (Entity, Model, Dao, Repositories)
  • Gerar features CRUD (create, list, find, update, delete)
  • Gerar features customizadas em PascalCase
  • Criar agregados dentro de um domínio existente
  • Gerar Migration, Factory e Tests de cada artefato
  • Registrar rotas idempotentes (append por método + URI)
  • Respeitar caminhos/namespaces vindos da config
  • Pular arquivos já existentes (nunca sobrescreve)

✗ O CqFeature não faz

  • Sobrescrever arquivos existentes (eles são skipped)
  • Mudar a arquitetura DDD ou criar novos tipos de feature
  • Rodar migrations ou tocar o banco de dados
  • Exigir Orchestra Testbench (testes em PHPUnit puro)
  • Publicar no Packagist público (distribuição por VCS privado)
  • Presets/perfis nomeados de config (apenas um arquivo de config)

Instalação

O pacote é distribuído por VCS privado (CqPlace/CqFeature). Adicione o repositório ao composer.json do projeto consumidor:

{
    "repositories": [
        {
            "type": "vcs",
            "url": "https://github.com/CqPlace/CqFeature.git"
        }
    ]
}

Em seguida, instale via Composer:

composer require cq/cqfeature

O auto-discovery do Laravel registra o Cq\CqFeature\Laravel\CqFeatureServiceProvider automaticamente (declarado em extra.laravel.providers). Nada mais é necessário para começar a usar o comando.

Início rápido

Gere um domínio CRUD completo com rotas em uma linha:

php artisan feature Financial Finance --features=crud --register-routes

O comando exibe um resumo dos arquivos que serão criados e pede confirmação antes de gravar. Para gerar sem confirmação (CI, scripts), use --force:

php artisan feature Financial Finance --features=crud --register-routes --force

Sem argumentos, o comando entra em modo interativo e pergunta módulo, domínio, features e registro de rotas:

php artisan feature
Nunca sobrescreve
Arquivos que já existem aparecem como SKIP no resumo e não são alterados. Rode o comando quantas vezes quiser com segurança.

Publicar a configuração

Os defaults já reproduzem o comportamento do cq/api. Para customizar, publique o arquivo de config:

php artisan vendor:publish --tag=cqfeature-config

Isso cria config/cqfeature.php no projeto. As chaves abaixo controlam tudo o que era hardcoded na lib original.

ChaveDefaultDescrição
root_namespaceAppRaiz PSR-4; vira o placeholder {{RootNamespace}} dos stubs
segments.modulesModulesPasta/namespace raiz dos módulos
segments.sharedSharedPasta da camada compartilhada do domínio
segments.featuresFeaturesPasta das features
segments.aggregatesAggregatesPasta dos agregados
paths.appappRaiz do código-fonte da aplicação
paths.tests_basetests/Feature/ModulesRaiz dos testes gerados

paths.migrations_basedatabase/migrationsRaiz das migrations geradas

Caminhos e namespaces

Mudar uma chave de caminho/namespace altera onde os arquivos são gerados e com qual namespace. Exemplo: gerar dentro de src/ com namespace Acme:

return [
    'root_namespace' => 'Acme',
    'segments' => [
        'modules'    => 'Modules',
        'shared'     => 'Shared',
        'features'   => 'Features',
        'aggregates' => 'Aggregates',
    ],
    'paths' => [
        'app'             => 'src',
        'tests_base'      => 'tests/Feature/Modules',
        'factories_base'  => 'database/factories/Modules',
        'migrations_base' => 'database/migrations',
    ],
];

Subpastas dos artefatos

As chaves shared_subfolders e feature_subfolders mapeiam cada tipo de artefato para a subpasta correspondente. Ex.: 'Controller' => 'Controllers', 'Entity' => 'Entities'. Ajuste-as se o seu projeto usa nomes de pastas diferentes.

Anti path-traversal preservado
A validação de bounds garante que os arquivos fiquem dentro da raiz de módulos configurada (segments.modules). Nomes com .. ou fora de PascalCase/PSR-4 são rejeitados.

Rotas

Com --register-routes, o pacote cria/atualiza o arquivo de rotas do domínio de forma idempotente (não duplica linhas já existentes). Tudo é configurável via routes.*:

ChaveDefaultDescrição
routes.baseroutes/api/modulesPasta-base dos arquivos de rota gerados
routes.prefixmodule_kebabEstratégia do prefixo do Route::group
routes.middleware['api','JWT','cors','localization']Middleware do grupo de rotas
routes.feature_mapcreate/list/find/update/deleteMapa feature → método HTTP + sufixo da URI

O feature_map default reproduz o REST clássico:

FeatureMétodoURI
createPOST{prefix}/{slug}
listGET{prefix}/{slug}
findGET{prefix}/{slug}/{id}
updatePUT{prefix}/{slug}/{id}
deleteDELETE{prefix}/{slug}/{id}

Stubs publicáveis

Os templates (.stub) ficam internos ao pacote, com o namespace base parametrizado pelo placeholder {{RootNamespace}}. Para customizá-los por projeto, publique:

php artisan vendor:publish --tag=cqfeature-stubs

Os stubs são copiados para stubs/cqfeature (ou o diretório definido em stubs.published_path). Edite-os à vontade.

Precedência (RN-02)

O StubRenderer resolve o template na ordem [publicado, pacote]. Assim, o stub publicado no projeto vence o stub interno do pacote. Se não houver versão publicada, o do pacote é usado.

Placeholders residuais
Após a renderização, qualquer placeholder não resolvido ({{...}}) é rejeitado com erro. Mantenha os placeholders dos stubs consistentes com os que o renderer fornece ({{RootNamespace}}, {{Module}}, {{Domain}} etc.).

Comando Artisan

O comando default é feature (configurável via command.name). A assinatura é montada em runtime a partir da config — trocar o nome na config altera o comando registrado.

Argumentos

ArgumentoObrigatório?Descrição
moduleSim*Pasta base do módulo (ex.: Financial)
domainSim*Nome do domínio (ex.: Finance)

* Se omitidos, são perguntados no modo interativo.

Opções

OpçãoDescrição
--features=Lista de features: create,list,find,update,delete, crud ou customizadas em PascalCase
--forceCria os arquivos sem pedir confirmação
--register-routesRegistra as rotas dos controllers gerados
--aggregate-of=Cria como agregado dentro de um domínio existente (ex.: Finance)
php artisan feature {module?} {domain?} {--features=} {--force} {--register-routes} {--aggregate-of=}

Assinatura completa. O nome feature é substituído por config('cqfeature.command.name') em runtime.

Exemplos

Domínio novo (CRUD + rotas)

Cria a camada Shared e as cinco features CRUD, além de registrar as rotas:

php artisan feature Financial Finance --features=crud --register-routes

Features padrão selecionadas

Gera apenas list e find (sem Shared duplicado se o domínio já existir):

php artisan feature Financial Finance --features=list,find

Feature customizada

O prefixo do domínio é adicionado automaticamente — informe o nome sem o prefixo. Abaixo cria a feature FinanceChangeInstallmentStatus:

php artisan feature Financial Finance --features=ChangeInstallmentStatus

Agregado de um domínio existente

Cria o domínio Invoice como agregado dentro de Finance (em Aggregates/):

php artisan feature Financial Invoice --aggregate-of=Finance --features=crud
Misturando features
Você pode combinar padrão e customizada: --features=crud,ChangeInstallmentStatus gera o CRUD completo mais a feature customizada.

Perguntas frequentes

A saída é igual à do FeatureMaker antigo?

Sim. Com a config default, a saída é idêntica (RN-01). O pacote inclui um teste de equivalência por snapshot que falha se houver qualquer divergência.

Como mudo o namespace base do código gerado?

Publique a config (--tag=cqfeature-config) e ajuste root_namespace. Os stubs usam o placeholder {{RootNamespace}}, então todo o código gerado passa a usar o novo namespace.

Como troco o nome do comando?

Altere command.name na config. Ex.: definir 'scaffold' faz o comando ser invocado como php artisan scaffold .... A assinatura é montada em runtime a partir dessa chave.

Os meus stubs publicados são realmente usados?

Sim — eles têm precedência sobre os do pacote (RN-02). Se o template existir no diretório publicado, ele é usado; caso contrário, cai no stub interno do pacote.

O comando sobrescreve arquivos existentes?

Não. Arquivos existentes são marcados como SKIP e mantidos intactos. É seguro rodar o comando repetidamente.

Preciso do Laravel completo para testar?

Não. A suíte usa PHPUnit puro (sem Orchestra Testbench), filesystem temporário e Illuminate\Container\Container para exercitar o provider.

Como rodo os testes do pacote?

composer test

Duas suítes: Unit (tests/Unit) e Features (tests/Features — E2E + equivalência por snapshot).
